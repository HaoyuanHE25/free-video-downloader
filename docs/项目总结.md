# 随下：项目总结

第一期「粘贴公开链接 → 看清标题和清晰度 → 保存到本地」已经可用；第二期补齐总结、字幕、导图和问答；第三期重构了工作台布局与视觉；第四期加上邮箱密码账号、每日免费额度与 ¥9.9 永久会员。产品范围仍以 [需求分析.md](需求分析.md) 为准，接口和扩展点仍以 [方案设计.md](方案设计.md) 为准，账号与支付细节见 [会员与支付.md](会员与支付.md)。本文记录做到哪、怎么验证、还留着什么。

## 做成了什么

单页工具。打开就能粘贴一条公开的 `http` / `https` 链接，解析出标题、封面、时长、平台和少数几档清晰度，再异步下载。完成后浏览器保存文件，同一张卡片上可以再次下载。解析成功后，下载、总结、字幕、导图和问答共用同一条地址。

页面从早期的暖色纸底和铜色升级为 Liquid Glass：半透明毛玻璃容器、低饱和冷色渐变背景、柔和阴影与 20px 圆角。宽屏下四个功能标签固定在左侧垂直排列，右侧内容自适应；窄屏回退为顶部横向标签。主要按钮高度至少 44px。会员卡是可展开的折叠卡，列出免费档与会员档权益，登录后可发起 ¥9.9 一次性购买。

后端是 FastAPI 对解析引擎的薄封装，外加抖音的公开详情请求。账号、会话、重置令牌、订单、会员和每日下载次数存在 SQLite（`data/app.sqlite3`），下载任务仍放在内存里，临时文件在系统临时目录的 `suixia/` 下。文件交给浏览器后删除，重启进程后任务清空、账号与会员保留。

## 平台

| 平台 | 实际做法 | 验证过的公开样例 |
| --- | --- | --- |
| YouTube | 不用用户 Cookie。默认网页客户端会被当成机器人，所以改用嵌入播放器通道，再用移动端与客户端通道补齐。本机有 `node` 时才把清晰度解全。同一档优先用带文件大小的直链，没有直链时用码率乘时长估算。 | `https://www.youtube.com/watch?v=anOPqj-49MI` 能解析出 1080p、720p、480p 和仅音频，大小不再是「大小未知」。 |
| Bilibili | 请求带 `Referer: https://www.bilibili.com/`。封面在 `hdslb.com` 上，改成同源 `/api/cover` 转发，避免防盗链。没写协议的分享链接会补上 `https://`。画面和声音分开的档位会列出来；没有 ffmpeg 时不能合成。 | `bilibili.com/video/BV1pix16iECa/...` 能解析出封面和 720p、480p、360p、仅音频。 |
| 抖音 | 不接收用户 Cookie。服务自己注册匿名 `ttwid`，用公开的 `x-secsdk-web-signature` 请求 `aweme/detail`。精选页认 `modal_id`，也认 `/video/数字` 和 `v.douyin.com` 短链。下载直链时带抖音 Referer。图文没有视频地址时直接说明。 | `https://www.douyin.com/jingxuan?modal_id=7695490636421680394` 能解析出封面、4:23、1080p 和 720p。抽查保存的文件是 MP4。 |

高于 1080p 的档位第一期不提供。直接媒体文件没有高度时，显示为「原文件」。

## 后续迭代

第二期在下载与工作台之上补齐解读能力：Markdown 总结、思维导图全屏与 PNG / SVG 导出、字幕 TXT / 时间戳 TXT / SRT / VTT 下载，以及基于字幕的连续问答。后端新增总结、字幕、导图和问答的 SSE 接口；字幕只读取平台或解析引擎已有的公开字幕，不下载整段视频做转写。

第三期重构界面：工作台从上下排列改为宽屏左侧垂直吸顶标签 + 右侧自适应内容，窄屏回退横向标签；视觉切换为 Liquid Glass。下载链路、SSE 事件结构和模型调用未改动。

第四期补账号与商业化：SMTP 验证码整体下线，改为邮箱 + 密码登录（bcrypt 哈希、重置令牌一次性使用）；非会员每天 3 次免费下载，按账号或 IP 原子计数，会员不限次数；接入 Stripe 一次性付款 ¥9.9 开通永久会员，会员只由 webhook 开通；首页新增「功能亮点」模块，并统一了全站文案口径。

## 边界

- 只接受公开链接。拒绝本机、内网、`.local`、`.internal`，以及解析不到公网地址的域名。有公网地址时，不因为多出来的一条不可用 IPv6 把整条链接拒绝掉。
- 不接收平台 Cookie、用户名或密码。封装层不向解析引擎传 Cookie 文件、用户名或密码。
- 免费档每天 3 次下载、同时最多 2 个；会员不限次数、同时最多 4 个。排队加下载最多 8 个。单文件免费 500MB / 会员 2GB，单次免费 10 分钟 / 会员 30 分钟。
- 不批量、不做字幕翻译。登录不是使用前提，未登录也能用每日 3 次额度。
- 抖音是唯一写在 `app/` 里的平台请求。其它平台继续走解析引擎，不把上游提取器源码拷进仓库。

## 怎么跑、怎么验

开发时开两个进程：FastAPI 在 `8000`，Vite 在 `5173`，页面把 `/api` 代理过去。构建出 `web/dist` 后，只开 `8000` 也能同时提供页面和接口。步骤见 [README.md](../README.md)。

`pytest` 不访问真实视频站，也不访问模型服务，覆盖清晰度收拢、非法链接、内网地址、B 站 Referer 和封面代理、YouTube 客户端、抖音精选页、字幕提取与分段、总结流与导出格式、下载完成后文件只能取一次、注册登录与密码重置、会话持久化、每日额度与会员支付幂等。当前 110 项通过。

页面上确认过：空链接、内网地址被拒绝、YouTube 和 B 站样例能解析、抖音这条精选链接能出封面和清晰度；四个功能标签点击与方向键切换正常；1280 / 1024 下左侧垂直标签吸顶、右侧内容自适应，360 下横向标签且不横向溢出。

## 还没做

批量链接、字幕翻译还没做。注册登录、账号数据库与会员支付已在第四期落地，细节见 [会员与支付.md](会员与支付.md)。

已知限制：

- 重定向到内网地址的防护没有改写解析引擎内部请求。
- 没有 `node` 时，YouTube 清晰度会变少。嵌入播放器通道也可能漏掉年龄限制等需要登录的视频。
- 没有 `ffmpeg` 时，分开的画面和声音只能列出，不能合成。
- 新开的终端可能还没刷新到 ffmpeg 的 PATH。
- 抖音图文、直播和超过 1080p 的档位不保存。平台签名以后失效时，要改 `app/douyin.py`，不能靠用户贴 Cookie。
