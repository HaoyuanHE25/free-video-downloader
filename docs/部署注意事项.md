# 随下：部署注意事项

本文是首次部署与后续发版前的操作清单：环境要求、安全规范、备份、防火墙、日志、回滚，以及需要负责人提供的资料与各阶段验证标准。口径以代码为准，涉及的环境变量名均来自 `app/` 各模块的实际读取项。

## 1. 部署形态与关键约束

- **同源单进程架构**：后端 FastAPI 同时托管前端构建产物（`app/main.py` 末尾挂载 `web/dist`），只需部署一个服务，Nginx/Caddy 反代到它。
- **必须单 worker**：下载任务（`app/jobs.py`）与总结任务（`app/summary_jobs.py`）的队列和状态都在进程内存里，多 worker 会导致任务状态互相不可见。启动命令不要加 `--workers`，保持默认单进程。
- **数据落盘位置**：
  - 账号/会员/配额数据库：`<项目根>/data/app.sqlite3`（SQLite，WAL 模式，可用 `MEMBERSHIP_DB_PATH` 改路径）。
  - 下载与总结的中间文件：系统临时目录 `%TEMP%/suixia`、`%TEMP%/suixia-summary`，属临时语义，重启丢失是预期行为，无需备份，但要保证磁盘余量（会员单文件上限 2GB）。
- **外部依赖**：解析引擎随 `requirements.txt` 安装；合成音视频需要系统安装 **ffmpeg** 并在 PATH 中（缺失时高清晰度合成会报错）。解析引擎必须保持较新版本——平台页面结构常变，旧版本会解析失败。
- **出站网络**：服务器需能访问各视频平台页面与 DeepSeek API；部分机房 IP 段可能被平台风控，部署前先实测（见 §7 预检查）。

## 2. 服务器环境要求

| 项目 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Linux x86_64（推荐 Ubuntu 22.04+/Debian 12） | Windows 亦可，命令按实际调整 |
| Python | 3.12+（本项目在 3.13 验证通过） | 与 `requirements.txt` 配套 |
| Node.js | 18+ | 仅构建机需要；可在本机构建后上传 `web/dist`，服务器不装 Node |
| ffmpeg | 4.x+，在 PATH 中 | 不装则高清合成不可用（免费/会员都不行） |
| 内存 | ≥ 2GB | 解析与 ffmpeg 合并有峰值 |
| 磁盘 | 系统盘 + 临时目录余量 ≥ 10GB | 临时目录与数据目录建议不在小容量分区 |
| 网络 | 出站可达平台与 DeepSeek；入站 80/443 | 见 §6 |
| 时区 | 服务器时区建议设为 Asia/Shanghai | 每日 3 次配额按服务器自然日 0 点重置，时区影响重置时刻 |

## 3. 依赖版本兼容性检查

- 以 `requirements.txt` 为准安装：`python -m pip install -r requirements.txt`；不要混用全局环境，用独立 venv。
- 解析引擎依赖条目要求较新版本，部署后运行 §7 的解析冒烟用例确认可用。
- `bcrypt` 默认 12 轮（`BCRYPT_ROUNDS` 未设置时），**生产禁止调低**；该变量只供测试加速。
- 构建前端时使用与开发一致的 Node 大版本；`package-lock.json` 提交在仓库中，构建机执行 `npm ci` 而非 `npm install`。
- 升级本项目时先在测试机跑 `pytest` 全量再上生产。

## 4. 安全配置规范

### 4.1 环境变量（`.env`，放在项目根，代码自动加载）

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `DEEPSEEK_API_KEY` | 是 | 总结/问答/导图功能依赖；缺失时对应接口报「还没有配置总结服务」 |
| `DEEPSEEK_MODEL` | 否 | 不设用默认模型 |
| `STRIPE_SECRET_KEY` | 是 | **不配置时支付进入模拟模式（fake）**，生产必须配置真实密钥 |
| `STRIPE_WEBHOOK_SECRET` | 是 | 缺失时回调直接报「未配置 STRIPE_WEBHOOK_SECRET」 |
| `PUBLIC_BASE_URL` | 是 | 如 `https://你的域名`，用于支付回跳与密码重置链接，必须是用户可访问的对外地址 |
| `TRUST_PROXY` | 是（反代部署时） | 设为 `1`，否则按 IP 计次会把代理 IP 当成用户 IP，且 Cookie 的 Secure 判定可能出错 |
| `COOKIE_SECURE` | 否 | 反代已设 `TRUST_PROXY=1` 时可不设；如仍要强制 HTTPS Cookie 则设 `1` |
| `ALLOWED_ORIGINS` | 否 | 同源部署无需配置；仅当前后端分离时填写前端来源 |
| `MEMBERSHIP_DB_PATH` | 否 | 默认 `<项目根>/data/app.sqlite3`；建议指向持久化磁盘的固定路径 |

### 4.2 规范要点

- `.env` 权限设为 `600`，不入 git（已在 `.gitignore`），不通过代码库或聊天工具传输；换机部署重新下发。
- 服务器登录：禁用密码登录、用 SSH 密钥；应用以非 root 专用账号运行。
- FastAPI 的 `/docs`、`/redoc` 已在代码中关闭（`docs_url=None`），无需额外处理。
- 数据库文件 `data/app.sqlite3` 权限收紧为应用账号可读写；目录不放在 Web 可写路径。
- Stripe Webhook 密钥只存 `.env`；回调已做签名校验与幂等（事件 ID 去重），不要绕过回调手工开会员。
- 依赖安装走官方源，锁定版本，避免供应链风险。

## 5. 数据备份策略

| 对象 | 方式 | 频率 | 恢复目标 |
| --- | --- | --- | --- |
| `data/app.sqlite3`（含 WAL） | `sqlite3 data/app.sqlite3 ".backup '/backup/app-YYYYMMDD.sqlite3'"` 或 `VACUUM INTO`；**不要直接 cp 正在写的库文件** | 每日 1 次，保留 14 天 | 数据丢失 ≤ 24h |
| `.env` | 加密后存放在代码库之外（如密码管理器） | 每次变更时 | 可快速重建服务 |
| `web/dist` | 由 git 仓库 + 构建机随时可重建，无需备份 | — | — |
| 临时目录 | 不备份 | — | — |

- 恢复演练：每季度做一次「备份文件 → 恢复到测试机 → 启动服务 → 登录验证」的完整演练。
- 代码迁移兼容性：`app/membership.py::_migrate` 只做加列与删废弃表，回滚旧版本代码遇到新库列多余字段不受影响，但仍建议回滚前先备份。

## 6. 端口与防火墙

- 应用只监听本机：`python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`，**不要把 8000 暴露公网**。
- 反向代理（Nginx/Caddy）监听 80/443：80 跳转 443；443 转发到 127.0.0.1:8000，并带 `X-Forwarded-For`、`X-Forwarded-Proto` 头。
- 防火墙（如 ufw）：仅放行 22（限制来源 IP 更佳）、80、443；明确拒绝 8000。
- SSE 流式接口（总结/问答）需在反代上关闭响应缓冲（`proxy_buffering off`）并放宽读超时（≥ 300s），否则前端看不到流式输出。
- 下载接口耗时最长 30 分钟（会员），反代对应路由的 `proxy_read_timeout` 建议不低于 1900s，或对 `/api/download` 单独放宽。

## 7. 部署前预检查（按顺序执行）

| # | 步骤 | 通过标准 |
| --- | --- | --- |
| 1 | 代码与依赖：服务器拉取指定 commit，建 venv 装 `requirements.txt` | 安装无报错，`pytest` 全量通过 |
| 2 | ffmpeg：`ffmpeg -version` | 可执行且 ≥ 4.x |
| 3 | 解析冒烟：启动后 `POST /api/parse` 一条真实公开视频链接 | 返回清晰度列表，不出现「服务器还没有安装解析引擎」 |
| 4 | 配置核对：对照 §4.1 逐项确认 `.env`，重点确认支付密钥为真实值（非模拟模式）与 `PUBLIC_BASE_URL` | `GET /api/me` 正常；发起一次测试支付能跳转 Stripe |
| 5 | 出站连通：服务器 curl 平台首页与 DeepSeek API | 均 200/正常响应 |
| 6 | 反代与证书：`curl -I https://域名` | 证书有效，301 到 443，响应头含正确转发头 |
| 7 | Webhook：Stripe Dashboard 配置 `https://域名/api/billing/stripe/webhook`（以代码路由为准）并放行测试事件 | 回调日志显示签名校验通过、事件幂等落库 |
| 8 | 前端产物：确认 `web/dist` 为最新构建（检查 `assets` 哈希文件名与 `index.html` 时间戳），且 6 处占位域名已替换为真实域名 | 打开首页无 404 资源、canonical/sitemap 指向真实域名 |
| 9 | 权限：`.env` 600、`data/` 归属应用账号、服务以非 root 运行 | `ls -l` 核对 |
| 10 | 基线备份：上线前手工执行一次 §5 数据库备份 | 备份文件可打开（`PRAGMA integrity_check` 通过） |

## 8. 回滚预案

1. **发版前**：记录当前 git commit 与备份点（代码回滚目标 + 数据库备份文件名），写入发布单。
2. **应用回滚**：`git checkout <上一发布 commit>` → 重建 venv（如依赖变化）→ 重新构建/上传 `web/dist` → 重启服务 → 执行 §9 验证。全程预期 ≤ 10 分钟。
3. **数据库回滚**：停服 → 用最近一次 `.backup` 文件恢复 → 启动 → 抽查一个账号登录与配额记录。回滚会丢失备份之后的注册/支付数据，需在回滚公告中说明。
4. **配置回滚**：保留上一版 `.env` 的加密副本，替换后重启即可。
5. **回滚触发标准**：核心流程（解析、下载、登录、支付回调）任一不可用且 30 分钟内无法热修，或出现数据写坏迹象，立即回滚。

## 9. 部署完成后的验证要点

- **冒烟主链路**：游客状态解析 → 下载一个小视频 → 校验文件可播放；重复 4 次确认第 4 次被「今日次数用完」拦截。
- **账号链路**：注册 → 登出 → 登录 → 忘记密码邮件链接可打开并重置成功。
- **支付链路**：用 Stripe 测试模式完成一次付款 → webhook 回调后会员状态变更 → 免费档限制解除。
- **AI 链路**：对一条视频发起总结（流式逐字出现）、导图、提问各一次。
- **Cookie 与会话**：确认浏览器 Application 面板中会话 Cookie 带 `Secure`/`HttpOnly`；关浏览器重开后仍保持登录。
- **多视口抽查**：375px / 768px / 1280px 各打开一次首页，无横向溢出、无控制台报错。
- **SEO 文件**：`/robots.txt`、`/sitemap.xml`、`/llms.txt` 可访问且域名正确。

## 10. 上线后监控建议

| 监控项 | 方式 | 告警阈值建议 |
| --- | --- | --- |
| 进程存活 | systemd 托管 + `Restart=always`；外部拨测 `GET /` 与 `GET /api/me` 每 1–5 分钟 | 连续 2 次失败告警 |
| HTTPS 证书 | 拨测工具监控到期日 | 剩余 14 天告警 |
| 磁盘空间 | 监控临时目录与数据目录 | 使用率 > 80% 告警 |
| 数据库健康 | 每日备份任务退出码 + `integrity_check` | 备份失败即告警 |
| 业务错误 | 采集 uvicorn 5xx 日志计数（§建议：启动时显式把日志级别调到 INFO 才能看到业务日志） | 5 分钟内 5xx > 5 条告警 |
| 支付回调 | Stripe Dashboard Webhook 端点失败率 | 任一失败即告警 |
| 解析成功率 | 每日抽 3 条主流平台链接冒烟 | 连续失败说明引擎需升级 |
| 出账用量 | DeepSeek 用量页 | 超日预算 80% 告警 |

- 日志轮转：uvicorn 输出经 systemd journald 或写入文件后配 logrotate，保留 ≥ 14 天；不要把日志写进临时目录。
- 变更纪律：每次发版走「预检查 §7 → 验证 §9 → 记录发布单」三步；平台解析类失败优先升级解析引擎版本而非改代码。
