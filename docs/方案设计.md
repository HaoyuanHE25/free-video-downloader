## 为什么用库封装

下载能力全部交给一个第三方解析库。仓库不复制它的源码，也不改它的提取器。

我们只留一层薄封装：

- 校验链接是不是公开的 `http` / `https`，并拒绝本机和内网目标。
- 把解析结果里的格式列表收成最多四档。
- 用后台线程下载，记录进度，再把临时文件以附件形式交给浏览器。
- 限制同时下载数、单文件大小和单次时长。

平台规则经常变。继续使用上游库，比在仓库里维护一份分叉的提取器更稳。封装层不要通过 Cookie 文件、用户名或密码把账号凭证传给解析引擎。

合并分离的画面和声音需要本机 `ffmpeg` 在 `PATH` 里。没有 ffmpeg 时，只提供已经是单文件的格式，并在解析结果的 `hint` 里说明。

## 进程与目录

开发时开两个进程：

- Vite 开发服务器在 `5173`，页面请求 `/api`。
- FastAPI 在 `8000`。Vite 把 `/api` 代理过来，浏览器仍访问同源地址。
- FastAPI 对 `http://localhost:5173` 和 `http://127.0.0.1:5173` 放开 CORS，便于直接打接口。

`web/dist` 存在时，FastAPI 在接口之外托管这份构建结果，这样只开 `8000` 也能看构建后的页面。

```
app/main.py         接口、CORS、限额入口；有构建产物时托管 web/dist
app/downloader.py   链接校验、解析引擎调用、清晰度收拢。总结实现后仍只负责清晰度和下载
app/jobs.py         下载任务的内存队列、并发槽位、临时目录
app/subtitles.py    视频总结实现时新增：平台字幕与引擎字幕只取字幕
app/summary.py      视频总结实现时新增：DeepSeek 调用和 JSON 校验
app/summary_jobs.py 视频总结实现时新增：总结任务，不放进 jobs.py
web/                Vue 3 + Vite + Tailwind
tests/test_api.py   不访问真实视频站的接口测试
```

临时文件放在系统临时目录的 `suixia/` 下，每个任务一个子目录。不把视频提交进仓库。

## 接口

所有接口都在本机使用，路径前缀 `/api`。错误时返回 `{"detail": "人话原因"}`。

### `POST /api/parse`

请求：`{ "url": "https://..." }`

行为：校验链接后只发起一次不下载的解析请求，并关闭播放列表展开。不下载文件。

成功时：

```json
{
  "title": "标题",
  "thumbnail": "https://...",
  "duration": 65,
  "platform": "YouTube",
  "ffmpeg": true,
  "hint": null,
  "formats": [
    {
      "format_id": "137+251",
      "label": "1080p",
      "ext": "mp4",
      "filesize": 8400000,
      "height": 1080,
      "audio_only": false,
      "needs_merge": true
    }
  ]
}
```

- `thumbnail` 一般是原始封面地址。B 站封面在 `hdslb.com` 上，经常是 `http://`，直接给浏览器会因 Referer 防盗链失败。解析结果改成同源的 `/api/cover?url=`，并把 `http` 换成 `https`。该接口只转发 `hdslb.com` 的图片，请求时带 `Referer: https://www.bilibili.com/`。
- 解析和下载 B 站、`b23.tv` 链接时，传给解析引擎的请求头同样带这个 Referer 和 `Origin`。其它网站不加这对请求头。
- 没写 `http://` 或 `https://`、但看起来是域名路径的文本，会补成 `https://` 再校验。B 站分享链接经常是这种写法。
- B 站普通清晰度是分开的画面和声音。没有 ffmpeg 时这些档位仍然列出来；真正保存时会说明需要安装 ffmpeg。档内如果已有带声音的单文件，优先用单文件。
- 同一清晰度优先用带 Content-Length 的直链，画面和声音分开时把两边的大小相加。只有 HLS 清单、没有文件大小时，用码率乘时长估算。两者都没有时 `filesize` 为 `null`。
- `hint` 在没有 ffmpeg 时提示只能保存单文件。
- 没有可保存档位时返回 422，`detail` 为「没有可保存的公开清晰度」。
- 平台不支持、链接无效、超时，分别写成「平台暂不支持」「链接无效」「解析超时，请稍后再试」。需要登录的内容说明本站只保存公开视频。

### `POST /api/download`

请求：`{ "url": "https://...", "format_id": "137+251" }`

立刻返回 `{ "job_id": "<32位十六进制>" }`。实际下载在后台线程里进行。`format_id` 只允许字母、数字、点、下划线、加号和短横线，用来挡住不是清晰度标识的字符串。

正在排队加正在下载的任务超过 8 个时返回 429。

### `GET /api/jobs/{id}`

```json
{
  "id": "...",
  "status": "queued",
  "progress": 0.4,
  "filename": null,
  "error": null
}
```

`status`：`queued`、`downloading`、`finished`、`error`。`progress` 为 0 到 1。完成后带 `filename`。失败时 `error` 是给页面展示的中文。未知任务返回 404。

### `GET /api/jobs/{id}/file`

仅在 `finished` 后可用。响应头 `Content-Disposition: attachment`，正文是文件。发送结束后删除该任务的临时目录，并把任务从内存移除。未完成返回 409，已取走或不存在返回 404。

### `POST /api/summary`

视频总结实现时新增。不复用下载任务。

请求：`{ "url": "https://..." }`

先做和解析相同的公开链接校验，立刻返回 `{ "job_id": "<32位十六进制>" }`。正在排队加正在总结的任务超过 4 个时返回 429。未配置 `DEEPSEEK_API_KEY` 时返回「还没有配置总结服务」，解析和下载照常可用。一条字幕都没有时返回 422，`detail` 为「这条公开视频没有可用字幕，暂时无法总结」。

### `GET /api/summary/{id}`

```json
{
  "id": "...",
  "status": "queued",
  "error": null,
  "result": null
}
```

`status`：`queued`、`fetching`、`summarizing`、`finished`、`error`。未知任务返回 404。完成后 `result` 为：

```json
{
  "outline": "一段话",
  "points": ["要点"],
  "chapters": [{ "title": "章节名", "start": 12.0, "summary": "这一段在讲什么" }],
  "transcript": [{ "start": 0.0, "end": 3.2, "text": "字幕" }],
  "truncated": false
}
```

`transcript` 是字幕原文，供页面展开。任务放在进程内存里，超过 30 分钟清掉。字幕临时文件在模型返回后删除。

### 流式接口（第二期）

下面四个接口都返回 `text/event-stream`，由 `app/sse.py` 统一封装：15 秒心跳，客户端断开即停止生成，业务异常以 `error` 事件收尾（入参校验失败仍用普通 JSON 状态码）。它们不占用下载队列。

| 接口 | 请求体 | 主要事件顺序 |
| --- | --- | --- |
| `POST /api/summary/stream` | `{ "url": "https://..." }` | `meta` → `status` → `stats` → `segment`* → `status` → `delta` / `point`* → `outline` → `chapter`* → `status` → `mindmap` → `done` |
| `POST /api/subtitles/stream` | `{ "url": "https://..." }` 或 `{ "text": "..." }` | `meta` → `status` → `stats` → `segment`* → `done` |
| `POST /api/mindmap/stream` | 同上，`url` 与 `text` 二选一 | `meta` → `status`* → `tree` → `mermaid` → `done` |
| `POST /api/summary/ask/stream` | `{ "question": "...", "history": [...], "context": {...}, "text": "...", "url": "..." }` | `meta` → `status` → `delta`* → `done` |

- 字幕接口的 `done.data.result.exports` 带 `plain`、`timed`、`srt`、`vtt` 四种文本，前端直接用 `Blob` 下载，不新增下载接口。
- 导图接口在 `tree` 事件下发结构树，`mermaid` 事件携带同结构的源码文本；页面渲染以 `tree` 为准。
- 问答请求里 `history` 只取最近 6 轮，`text` 与 `context` 总量受 `QA_CONTEXT_LIMIT`（12,000 字符）限制；未给 `context` 和 `text` 时按 `url` 取字幕。
- 字幕或资料直接粘贴时，`text` 上限 120,000 字符；导图文本按缩进层级解析。

## 清晰度怎么收拢

不把解析引擎的原始格式列表原样返回。按画面高度分三档，每档只留一条：

| 档位 | 高度 | 标签 |
| --- | --- | --- |
| 高 | 721–1080 | 1080p |
| 中 | 481–720 | 720p |
| 低 | 1–480 | 480p |

高于 1080 的格式第一期不提供。同一档里按码率、高度、是否 mp4、体积排序，取得分最高的一条。按钮上的文字用实际高度：1000 及以上写 1080p，700 及以上写 720p，480 及以上写 480p，更低写实际像素，例如 240p。直接媒体地址如果没有高度和编码信息，且也没有其他画面档，就额外给一档「原文件」，避免把可保存的单文件丢掉。

YouTube 现在的提取依赖 JavaScript 运行时。本机有 `node` 时，封装会把 JS 运行时指定为 node，并允许解析引擎内置的挑战求解组件去解挑战。求解脚本不放进仓库。没有 node 时不传这两项，清晰度可能变少。默认的网页播放器在部分网络上会要求确认不是机器人；解析 `youtube.com`、`youtu.be` 时改用嵌入播放器通道，再用移动端与客户端通道补齐。不接收用户的 YouTube Cookie。

抖音精选页的地址是 `jingxuan?modal_id=`，上游目前只认 `/video/数字`，而且会向使用者要 Cookie。这条链路不接收用户 Cookie。服务自己向 `www.douyin.com` 注册匿名 `ttwid`，用公开的 `x-secsdk-web-signature` 请求 `aweme/detail`。短链 `v.douyin.com` 先跟随重定向再取视频号。只保存返回的公开 mp4 直链，下载时带 `Referer: https://www.douyin.com/`。图文没有视频地址时会说明暂时只能保存视频。

- 该条本身带声音：`format_id` 就是它自己的 id，`needs_merge` 为 false。
- 该条只有画面，且本机有 ffmpeg，并且存在一条纯音频：`format_id` 写成 `画面id+音频id`，`needs_merge` 为 true，扩展名按 mp4 合并。
- 没有 ffmpeg：这一档退回「已经带声音的单文件」；如果没有，就不出这一档。
- 纯音频另作一档，标签「仅音频」，优先码率更高的一条。它不需要合并。

默认选中顺序由前端决定：格式数组从高到低排列，选中第一条非纯音频；若只有音频，就选音频。这就是「不超过 1080p 的最佳项」。

## 字幕从哪来

这一节随视频总结一起实现。解析出标题之后即可取字幕，不必先保存视频。没有可用字幕就停止，不下载整段视频或音轨，也不做语音转写。

同一条链接先走平台字幕，没有再交给解析引擎，只取字幕、不下载视频。字幕地址同样要过 `validate_public_url`。多 P 只总结地址里这一 P。播放列表不展开。

| 平台 | 第一选择 | 没有字幕时 |
| --- | --- | --- |
| Bilibili | `https://api.bilibili.com/x/web-interface/view` 取 `cid`，再请求 `https://api.bilibili.com/x/player/v2?bvid=&cid=`。请求带 `Referer: https://www.bilibili.com/`。优先 `zh-CN`、`ai-zh`，其次其它 `zh*`，再 `en`。字幕 JSON 用 `body[].from`、`to`、`content` | 交给解析引擎只写字幕文件 |
| YouTube | 不另写 timedtext。解析引擎已经在用它的播放器客户端拿字幕，这里直接让它跳过视频下载，并允许自动字幕。语言顺序与 B 站相同 | 页面说明没有可用字幕 |
| 抖音 | 只读现有公开详情里的字幕地址。不把用户 Cookie 交给解析引擎，所以抖音不走引擎字幕 | 页面说明没有可用字幕 |

字幕正文超过约 6 万字时，只把前面的部分交给模型，结果里带 `truncated: true`，页面写明只覆盖了开头。

## 模型

服务端调用 DeepSeek 的 OpenAI 兼容接口：

- 地址 `https://api.deepseek.com/chat/completions`
- 模型默认 `deepseek-v4-flash`。`deepseek-chat` 已于 2026-07-24 停用。可用环境变量 `DEEPSEEK_MODEL` 覆盖
- 关闭思考模式（`thinking.type` 为 `disabled`），避免把推理过程当总结
- `response_format` 为 `{"type": "json_object"}`
- 密钥只读环境变量 `DEEPSEEK_API_KEY`，不进仓库、不进浏览器、不写进日志
- 模型超时约 120 秒。HTTP 401、429、5xx 分别写成密钥无效、服务繁忙、总结失败，不把上游英文直接给页面

发给模型的用户消息是带时间的字幕行，例如 `[00:12] ……`。系统提示要求只根据这些行写中文 JSON，不补充字幕里没有的事实。章节的 `start` 必须落在某条字幕的起点上；对不上的章节在服务端丢掉。字幕原文不由模型改写，页面用提取结果。

模型要返回的 JSON：

```json
{
  "outline": "一段话",
  "points": ["要点"],
  "chapters": [{ "title": "章节名", "start": 12.0, "summary": "这一段在讲什么" }]
}
```

`points` 最多 8 条，`chapters` 最多 12 条。字段缺失或不是合法 JSON 时，页面写「总结没有生成，请重试」，不展示半截内容。

不在这一档：翻译、画面理解、批量链接，以及在 `POST /api/parse` 里调用模型。

## AI 应用专项

本节集中回答四个问题：AI 用在哪、值在哪、为什么这么选、接下来往哪走。接口细节见上一节「模型」。

### 应用场景矩阵

| 模块 | AI 角色 | 实现路径 | 未配置 / 失败时的降级 |
| --- | --- | --- | --- |
| 总结 | 字幕 → 结构化摘要（大纲 / ≤8 要点 / ≤12 带时间戳章节） | 带时间戳字幕行 → JSON 模式流式调用 → 服务端校验落点 → SSE 逐段下发 | 503「尚未配置」，下载 / 字幕 / 导图不受影响 |
| 问答 | 字幕限定域内的多轮追问 | 字幕截断为 1.2 万字符上下文 + 严格拒答提示词 → Markdown 回答 | 同上，依赖同一密钥 |
| 导图 | 总结结构 → Mermaid 节点树 | 复用总结的结构化结果，前端确定性转换（非模型调用） | 无 AI 也可用：粘贴提纲仍能生成导图 |
| 字幕 | 不涉及 AI | 解析引擎抓取内置字幕，服务端做语义分段 | 与 AI 配置无关，始终可用 |

AI 的调用边界刻意收窄：只在「字幕已存在」之后介入，解析、下载、清晰度、限额等核心链路全部零模型依赖——模型故障不会波及主业务。

### 量化收益（口径：代码实测约束，非实验室基准）

| 维度 | 量化结果 | 实现机制 |
| --- | --- | --- |
| 时间效率 | 大纲首行随生成逐字下发，不必等整个 JSON（模型超时上限 120 秒，正常数秒内开始出字） | 流式 JSON 解析器逐字段切分，outline / point 事件先到先渲染 |
| 阅读效率 | 一条任意时长视频收敛为固定输出上限：≤8 要点 + ≤12 章节，章节时间点可直接跳转原片 | 输出结构在提示词与服务端双重约束，超限字段丢弃 |
| 问答准确性 | 上下文窗口固定 1.2 万字符；章节 `start` 必须命中字幕起点，对不上的服务端直接丢弃 | 截断 + 结构校验双重防幻觉 |
| 成本 | 每条视频总结固定 1 次调用、每次提问 1 次调用；输出长度被 8/12 上限锁死，单次成本可预估；未配置密钥时成本为零（功能降级而非报错） | 请求级幂等与结构上限；降级路径见上表 |

### 与传统实现的差异化

| 能力点 | 传统规则式方案 | 本项目（LLM 方案） |
| --- | --- | --- |
| 大纲生成 | 抽取式：截取关键词句拼段，语义不连贯 | 生成式：按字幕语义重组，可加粗、分段、列点 |
| 章节划分 | 均匀切片或按词频突变点，标题靠模板 | 语义完整章节，标题概括内容且时间戳可回跳 |
| 问答 | 关键词检索字幕原文，命中即返回 | 限定域理解式作答，跨段落综合后用 Markdown 组织 |
| 导图 | 依赖人工输入结构 | 从总结结构自动派生，粘贴提纲亦可用 |

规则式的优势被保留的部分：字幕原文不经模型改写，页面直接用引擎提取结果——准确性敏感的内容不交给生成模型。

### 技术选型依据

- **DeepSeek（`deepseek-v4-flash`，OpenAI 兼容接口）**：原生 JSON 模式 + 流式输出正好覆盖「结构化摘要」与「边生成边展示」两个硬需求；中文摘要质量适合主要面向中文视频的场景；属低价档模型，成本可预估（见上表）。`deepseek-chat` 已于 2026-07-24 停用，模型名走 `DEEPSEEK_MODEL` 环境变量，可随时替换为任何 OpenAI 兼容端点。
- **关闭思考模式**：总结是提取重组任务，推理过程只会增加延迟和 token，无质量收益。
- **不在解析阶段调用模型**：解析要快且免费额度敏感，模型调用集中在用户主动触发的总结 / 问答。
- **不选本地小模型**：无需 GPU 运维，密钥级降级路径已把外部依赖风险限制在单个功能面。

### 落地可行性保障

- 密钥只读环境变量，不进仓库、不进浏览器、不写日志（见「安全约束」）。
- 上游错误分类映射为中文文案（401 密钥无效 / 429 繁忙 / 5xx 总结失败），不透出英文原文。
- 全部模型交互在测试中用假对象覆盖，`pytest` 不访问真实模型服务（110 项通过）。

### 迭代规划

1. **摘要缓存**：同一链接的总结结果按字幕指纹缓存复用，二次访问零模型成本。
2. **无字幕视频兜底**：接入语音转写（ASR）补齐字幕缺失场景，把 AI 覆盖面从「有字幕的公开视频」扩展到大部分公开视频。
3. **问答升级 RAG**：字幕超过 1.2 万字符时由截断改为向量检索取段，长视频问答质量不衰减。
4. **多语言摘要**：字幕为英文时按用户语言偏好输出，前端 i18n 基建（中英双语）已就绪。
5. **导图直达**：跳过总结面板，字幕一键生成导图，缩短 AI 能力的触达路径。

## 第二期扩展：Markdown、导图全屏与字幕下载

这一期在已有的工作台四模块上增量实现，不改变下载链路和 SSE 协议。

### Markdown 渲染

- 前端新增 `web/src/components/MarkdownView.vue`，使用 `marked`（GFM、保留换行）把模型文本转成 HTML，再交给 `DOMPurify` 过滤，外链统一加 `target="_blank"` 和 `rel="noopener noreferrer"`。`marked` 自身不做 HTML 过滤，不能直接 `v-html`。
- 统一排版样式在 `web/src/style.css` 的 `.markdown-body`：标题、段落、列表、加粗、引用、代码块、表格、链接都使用 Liquid Glass 的冷色系（强调蓝 `#4f6da8`、浅蓝底 `#f2f5fb`、墨色 `#1b1f2a`）。`inline` 变体用于要点列表，避免短句被包成独立段落。
- 总结大纲、要点、章节摘要和问答回答都走这套渲染；流式接收过程中直接增量渲染。
- 模型系统提示允许并要求 Markdown：`outline`、`chapters[].summary` 可用 `**加粗**`、`- 列表`、`### 小标题`，换行在 JSON 里写成 `\n`；`points` 每条仍保持一句话。问答回答同样使用 Markdown，引用字幕时带时间点。

### 思维导图全屏与导出

- 保持现有自绘 SVG 布局，不改渲染引擎，避免节点样式和曲线布局回归。
- 导图卡片的普通视图高度提升到 `75vh`（移动端 `62vh`，最小高度 320px），并保留滚动。
- 新增全屏弹层：`Teleport` 到 `body`，铺满视口，锁定页面滚动，`Esc` 或右上角按钮关闭。打开时按视口自动「适应屏幕」，支持按钮、滚轮缩放（20%–400%）和拖动平移；底部有操作提示。
- 导出使用普通视图中的完整 SVG 克隆，不受当前滚动和缩放影响：
  - PNG：默认 2x，可选 3x，白底，文件名 `思维导图-{根节点}-{时间}.png`；画布最长边限制 8192px，避免超出浏览器画布上限。
  - SVG：白底矢量，文件名同 PNG，适合打印和二次编辑。
  - 导出前把叶子节点和根节点的下划线样式写成 SVG 属性，避免组件 scoped CSS 在独立文件中失效。
- 普通视图与全屏弹层都提供导出入口。

### 字幕下载

- 后端 `app/summary_stream.py` 的字幕 `exports` 增加 `timed` 字段，复用 `to_plain(cues, with_time=True)`，输出形如 `[00:01] 正文`。
- 前端字幕面板在解析完成后提供「下载」区，四种格式直接通过 `Blob` 触发浏览器下载，保留原有「复制」区：
  - `TXT`：纯文本，无时间。
  - `时间戳 TXT`：每行带 `[分:秒]`。
  - `SRT`：标准字幕，可导入播放器/剪辑软件。
  - `VTT`：Web 播放器字幕。
- 文件名 `字幕-{YYYYMMDD-HHmm}.{ext}`，不新增下载接口，不改动 SSE 事件结构。

### 验收要点

- `pytest` 覆盖 `timed` 导出字段。
- `npm run build` 通过，页面在 856×434 和移动端宽度下不溢出。
- 浏览器实测：总结大纲出现真实加粗和列表、没有残留 `**`；导图全屏可缩放拖动，PNG 为 SVG 的 2 倍尺寸且白底；字幕四种格式按钮可见，SRT 与时间戳 TXT 能落盘。

## 任务、限额、清理

任务存在进程内存里，重启即空。字段包括 id、状态、进度、文件路径、展示文件名、错误、创建时间、临时目录。

- 全局同时下载最多 2 个。其余任务保持 `queued`，在信号量上等待。
- 单文件上限约 500MB（`500 * 1024 * 1024` 字节）。解析前设置的文件上限和下载完成后的文件大小都会检查。
- 单次下载约 10 分钟。进度回调里用单调时钟判断，超时则失败，页面提示换一条较短的公开视频。
- 创建新任务时清掉超过 30 分钟的旧目录。
- 文件成功回传后删除目录。前端若要「再次下载」，应重新 `POST /api/download`，不要假设旧文件还在。

进度来自解析引擎的下载进度回调。合并完成前进度最高记到 0.99，任务真正结束再记为 1。

视频总结使用 `summary_jobs.py` 里单独的内存队列，不占用上面的下载槽位。正在排队加正在总结最多 4 个，同样超过 30 分钟清掉。

## 安全约束

`validate_public_url` 在解析和下载之前运行：

- 只允许 `http` 和 `https`。空链接、其它协议、带用户名或密码的链接，都视为无效。
- 拒绝 `localhost`、`.local`、回环、私网、链路本地、保留地址和组播。主机名会先解析：一个公网地址都没有时拒绝。若同时有公网地址和无效的 IPv6（有的网络会这样），仍允许访问。
- 不向解析引擎传入 Cookie 文件、用户名或密码。
- `format_id` 做字符白名单，避免把任意引擎格式表达式从浏览器塞进来。
- 字幕地址在抓取前同样经过 `validate_public_url`。
- `DEEPSEEK_API_KEY` 只留在服务端环境变量里，不进仓库、不进浏览器、不写进日志。

这一层挡的是用户提交的链接。它不能替代部署时的网络隔离；第一期文档把这一点记为已知边界，不在应用里做提取器级别的重定向改写。

## 界面结构与配色

页面是单页，内容宽度最大 1080px。组件为：顶栏、首屏、解析输入、结果卡、工作台（总结 / 字幕 / 导图 / 问答）、能力卡、会员折叠卡、页脚。请求集中在 `web/src/api.js` 和 `web/src/summaryApi.js`。

结构：

- 顶栏约 56px，固定玻璃条：半透明白底、`backdrop-filter: blur(24px) saturate(...)`、底部一条浅描边。品牌「随下」；导航「能做什么 / 会员」；右侧是登录 / 账号入口。
- 首屏在未开始解析时显示：小标签「下载与解读」；主标题「任意平台视频，一键保存」，强调短语用低饱和蓝；副标题说明下载、总结、字幕、导图与问答共用同一条地址；下方三枚信任点（每天 3 次免费下载 / 不接收平台 Cookie / 文件保存在本地）。
- 主操作是最宽约 680px 的胶囊玻璃输入，右侧「解析」为深色玻璃按钮。解析中按钮不可重复点击；聚焦时描边变成中性蓝，不再出现橙色实线。
- 失败原因写在卡片里，不只用浏览器弹窗。
- 解析成功后一张深色玻璃结果卡：封面、标题、平台、时长、清晰度按钮、保存按钮。下载过程在同一张卡片里显示进度。
- 工作台四个标签固定为「总结 / 字幕 / 导图 / 问答」，都允许和下载共用同一条地址：
  - 宽屏（`lg`，即 1024px 起）：标签固定在左侧，236px 垂直吸顶栏（`lg:sticky lg:top-20`），每条包含图标块、标签和一句说明；右侧内容区自适应填充剩余宽度。
  - 窄屏：回到顶部横向玻璃标签栏（`glass-bar sticky top-14`），内容在下方单列。
  - 切换只改变显示，四个面板都保持挂载（`v-show`），以 `role=tablist/tab/tabpanel` 标注并支持方向键切换；地址不变时面板状态不丢。
- 能力卡三列：多平台、自选清晰度、手机可用。窄屏改为单列。
- 会员是折叠卡（`<details>`）：免费档列同时 2 个、500MB、10 分钟与每天 3 次；会员档列不限次数、4 个、2GB、30 分钟与 ¥9.9 一次买断。登录后可发起购买，支付细节见 [会员与支付.md](会员与支付.md)。
- 未开始解析时，主工具区下方展示「功能亮点」四张卡片（3 次/天、四档清晰度、5 种用法、¥9.9 永久会员），开始解析后隐藏，避免干扰主流程。
- 页脚固定一句版权说明。

视觉系统是 Liquid Glass：半透明毛玻璃容器、低饱和冷色渐变背景、柔和分层阴影、细腻圆角，交互元素风格统一。

## 验证

- `pytest`：假的解析引擎对象覆盖清晰度收拢、非法链接、内网地址、任务完成后取文件、取走后文件不可再取。
- 视频总结的 `pytest` 不访问视频站，也不访问 DeepSeek。用假的字幕响应和假的模型客户端覆盖：B 站字幕 JSON 能收成带时间的句子并选中中文轨；没有字幕时不调用模型，接口返回「这条公开视频没有可用字幕，暂时无法总结」；模型返回的章节时间对不上字幕时被丢掉；未配置密钥、模型返回非 JSON、字幕超长被截断。
- 页面：空链接、非法链接、解析成功后的清晰度切换、保存进度和浏览器下载。宽度收到手机尺寸时检查单列是否溢出。在 1280 / 1024 / 360 三种宽度确认四个标签可点击并用方向键切换：1280 和 1024 下左侧垂直标签吸顶、右侧内容自适应，360 下顶部横向标签且页面不横向溢出。总结面板查看一条带公开字幕的短视频：字幕默认收起，下载仍能完成。
- 真实网络只用于确认一条短的公开样例能解析出标题。下载链路的自动化不拉取长视频。
