# 随下：方案设计（第一期）

实现和扩展时以本文为准。产品范围见 [需求分析.md](需求分析.md)。第一期没有账号、数据库和支付。

## 为什么用库封装

下载能力全部交给 PyPI 上的 `yt-dlp`。仓库不复制它的源码，也不改它的提取器。

我们只留一层薄封装：

- 校验链接是不是公开的 `http` / `https`，并拒绝本机和内网目标。
- 把 `extract_info(..., download=False)` 的格式列表收成最多四档。
- 用后台线程下载，记录进度，再把临时文件以附件形式交给浏览器。
- 限制同时下载数、单文件大小和单次时长。

平台规则经常变。继续使用上游库，比在仓库里维护一份分叉的提取器更稳。封装层不要通过 `cookiefile`、`username`、`password` 把账号凭证传给 yt-dlp。

合并分离的画面和声音需要本机 `ffmpeg` 在 `PATH` 里。没有 ffmpeg 时，只提供已经是单文件的格式，并在解析结果的 `hint` 里说明。

## 进程与目录

开发时开两个进程：

- Vite 开发服务器在 `5173`，页面请求 `/api`。
- FastAPI 在 `8000`。Vite 把 `/api` 代理过来，浏览器仍访问同源地址。
- FastAPI 对 `http://localhost:5173` 和 `http://127.0.0.1:5173` 放开 CORS，便于直接打接口。

`web/dist` 存在时，FastAPI 在接口之外托管这份构建结果，这样只开 `8000` 也能看构建后的页面。

```
app/main.py         接口、CORS、限额入口；有构建产物时托管 web/dist
app/downloader.py   链接校验、yt_dlp.YoutubeDL 调用、清晰度收拢
app/jobs.py         内存任务、并发槽位、临时目录
web/                Vue 3 + Vite + Tailwind
tests/test_api.py   不访问真实视频站的接口测试
```

临时文件放在系统临时目录的 `suixia/` 下，每个任务一个子目录。不把视频提交进仓库。

## 接口

所有接口都在本机使用，路径前缀 `/api`。错误时返回 `{"detail": "人话原因"}`。

### `POST /api/parse`

请求：`{ "url": "https://..." }`

行为：校验链接后只调用 `extract_info(..., download=False)`，并设置 `noplaylist=True`。不下载文件。

成功时：

```json
{
  "title": "标题",
  "thumbnail": "https://...",
  "duration": 65,
  "platform": "YouTube",
  "ffmpeg": true,
  "hint": null,
  "formats": [
    {
      "format_id": "137+251",
      "label": "1080p",
      "ext": "mp4",
      "filesize": 8400000,
      "height": 1080,
      "audio_only": false,
      "needs_merge": true
    }
  ]
}
```

- `thumbnail` 一般是原始封面地址。B 站封面在 `hdslb.com` 上，经常是 `http://`，直接给浏览器会因 Referer 防盗链失败。解析结果改成同源的 `/api/cover?url=`，并把 `http` 换成 `https`。该接口只转发 `hdslb.com` 的图片，请求时带 `Referer: https://www.bilibili.com/`。
- 解析和下载 B 站、`b23.tv` 链接时，传给 yt-dlp 的请求头同样带这个 Referer 和 `Origin`。其它网站不加这对请求头。
- 没写 `http://` 或 `https://`、但看起来是域名路径的文本，会补成 `https://` 再校验。B 站分享链接经常是这种写法。
- B 站普通清晰度是分开的画面和声音。没有 ffmpeg 时这些档位仍然列出来；真正保存时会说明需要安装 ffmpeg。档内如果已有带声音的单文件，优先用单文件。
- 同一清晰度优先用带 Content-Length 的直链，画面和声音分开时把两边的大小相加。只有 HLS 清单、没有文件大小时，用码率乘时长估算。两者都没有时 `filesize` 为 `null`。
- `hint` 在没有 ffmpeg 时提示只能保存单文件。
- 没有可保存档位时返回 422，`detail` 为「没有可保存的公开清晰度」。
- 平台不支持、链接无效、超时，分别写成「平台暂不支持」「链接无效」「解析超时，请稍后再试」。需要登录的内容说明本站只保存公开视频。

### `POST /api/download`

请求：`{ "url": "https://...", "format_id": "137+251" }`

立刻返回 `{ "job_id": "<32位十六进制>" }`。实际下载在后台线程里进行。`format_id` 只允许字母、数字、点、下划线、加号和短横线，用来挡住不是清晰度标识的字符串。

正在排队加正在下载的任务超过 8 个时返回 429。

### `GET /api/jobs/{id}`

```json
{
  "id": "...",
  "status": "queued",
  "progress": 0.4,
  "filename": null,
  "error": null
}
```

`status`：`queued`、`downloading`、`finished`、`error`。`progress` 为 0 到 1。完成后带 `filename`。失败时 `error` 是给页面展示的中文。未知任务返回 404。

### `GET /api/jobs/{id}/file`

仅在 `finished` 后可用。响应头 `Content-Disposition: attachment`，正文是文件。发送结束后删除该任务的临时目录，并把任务从内存移除。未完成返回 409，已取走或不存在返回 404。

## 清晰度怎么收拢

不把 yt-dlp 的 `formats` 原样返回。按画面高度分三档，每档只留一条：

| 档位 | 高度 | 标签 |
| --- | --- | --- |
| 高 | 721–1080 | 1080p |
| 中 | 481–720 | 720p |
| 低 | 1–480 | 480p |

高于 1080 的格式第一期不提供。同一档里按码率、高度、是否 mp4、体积排序，取得分最高的一条。按钮上的文字用实际高度：1000 及以上写 1080p，700 及以上写 720p，480 及以上写 480p，更低写实际像素，例如 240p。直接媒体地址如果没有高度和编码信息，且也没有其他画面档，就额外给一档「原文件」，避免把可保存的单文件丢掉。

YouTube 现在的提取依赖 JavaScript 运行时。本机有 `node` 时，封装会把 `js_runtimes` 设为 node，并允许 yt-dlp 官方的 `ejs:github` 组件去解挑战。求解脚本不放进仓库。没有 node 时不传这两项，清晰度可能变少。默认的网页播放器在部分网络上会要求确认不是机器人；解析 `youtube.com`、`youtu.be` 时改用 `web_embedded`，再用 `mweb` 和 `android` 补齐。不接收用户的 YouTube Cookie。

抖音精选页的地址是 `jingxuan?modal_id=`，上游目前只认 `/video/数字`，而且会向使用者要 Cookie。这条链路不接收用户 Cookie。服务自己向 `www.douyin.com` 注册匿名 `ttwid`，用公开的 `x-secsdk-web-signature` 请求 `aweme/detail`。短链 `v.douyin.com` 先跟随重定向再取视频号。只保存返回的公开 mp4 直链，下载时带 `Referer: https://www.douyin.com/`。图文没有视频地址时会说明暂时只能保存视频。

- 该条本身带声音：`format_id` 就是它自己的 id，`needs_merge` 为 false。
- 该条只有画面，且本机有 ffmpeg，并且存在一条纯音频：`format_id` 写成 `画面id+音频id`，`needs_merge` 为 true，扩展名按 mp4 合并。
- 没有 ffmpeg：这一档退回「已经带声音的单文件」；如果没有，就不出这一档。
- 纯音频另作一档，标签「仅音频」，优先码率更高的一条。它不需要合并。

默认选中顺序由前端决定：格式数组从高到低排列，选中第一条非纯音频；若只有音频，就选音频。这就是「不超过 1080p 的最佳项」。

## 任务、限额、清理

任务存在进程内存里，重启即空。字段包括 id、状态、进度、文件路径、展示文件名、错误、创建时间、临时目录。

- 全局同时下载最多 2 个。其余任务保持 `queued`，在信号量上等待。
- 单文件上限约 500MB（`500 * 1024 * 1024` 字节）。yt-dlp 的 `max_filesize` 和下载完成后的文件大小都会检查。
- 单次下载约 10 分钟。进度回调里用单调时钟判断，超时则失败，页面提示换一条较短的公开视频。
- 创建新任务时清掉超过 30 分钟的旧目录。
- 文件成功回传后删除目录。前端若要「再次下载」，应重新 `POST /api/download`，不要假设旧文件还在。

进度来自 yt-dlp 的 `progress_hooks`。合并完成前进度最高记到 0.99，任务真正结束再记为 1。

## 安全约束

`validate_public_url` 在解析和下载之前运行：

- 只允许 `http` 和 `https`。空链接、其它协议、带用户名或密码的链接，都视为无效。
- 拒绝 `localhost`、`.local`、回环、私网、链路本地、保留地址和组播。主机名会先解析：一个公网地址都没有时拒绝。若同时有公网地址和无效的 IPv6（有的网络会这样），仍允许访问。
- 不向 yt-dlp 传入 `cookiefile`、`username`、`password`。
- `format_id` 做字符白名单，避免把任意 yt-dlp 格式表达式从浏览器塞进来。

这一层挡的是用户提交的链接。它不能替代部署时的网络隔离；第一期文档把这一点记为已知边界，不在应用里做提取器级别的重定向改写。

## 界面结构与配色

参考落地页的结构，不使用那套蓝色。页面是单页，组件为：顶栏、解析区、结果卡、能力卡、会员卡、页脚。请求集中在 `web/src/api.js`。

结构：

- 顶栏约 56px，固定，浅色半透明。品牌「随下」；链接「下载 / 清晰度 / 会员」；右侧「登录」不可用，并标明即将开放。
- 主标题 36px、字重 900：「任意平台视频，一键保存」。其中「一键保存」用铜色。
- 副标题：粘贴公开链接，自选清晰度，电脑和手机都能下。
- 主操作是一条最宽约 600px 的胶囊输入，右侧全圆角「解析」。解析中按钮不可重复点击。
- 失败时在卡片里写原因，不只用浏览器弹窗。
- 成功后一张白卡片：封面、标题、平台、时长、清晰度按钮、保存按钮。下载过程在同一张卡片里显示进度。
- 三列能力：多平台、自选清晰度、手机可用。窄屏改为单列。
- 两列会员：免费可用（单条链接、自选清晰度、保存到本地）；会员即将开放（批量、字幕翻译、视频总结）。会员按钮不能扣费。
- 页脚固定一句版权说明。

配色：

| 用途 | 色值 |
| --- | --- |
| 页面底 | `#f6f1e8` |
| 顶栏 | `#fffdf8` |
| 标题、主按钮底 | `#1c1917` |
| 强调短语、选中清晰度描边 | `#c2410c` |
| 主按钮文字 | `#fffdf8` |
| 输入描边 | `#e7e0d6` |
| 卡片底 | `#fffcf8` |
| 卡片边框 | `rgba(28, 25, 23, 0.06)` |
| 标签 | `#78716c` |
| 「即将开放」 | `#9a3412` |

阴影略带暖色。不使用 `#1777ff` 或 `#2563eb`。焦点环用铜色。按钮使用指针光标，高度至少 44px。尊重 `prefers-reduced-motion`。图标用 SVG，不用 emoji 当图标。

## 扩展时接在哪一层

| 能力 | 接入位置 | 不要做的事 |
| --- | --- | --- |
| 支付、会员 | 新的账号与订单模块。会员卡按钮目前是禁用状态，只在订单真实有效之后才打开批量额度 | 不要在 `downloader.py` 里判断付款；没有数据库时不要假装已扣费 |
| 数据库 | 替换 `jobs.py` 的内存字典，保持现有四个接口的形状 | 不要把任务状态只写在浏览器里 |
| 登录 | 独立的身份层，再把限额从「全局」改成「按人」 | 不要用平台 Cookie 冒充本站登录 |
| 字幕、翻译 | 新的任务类型和新接口 | 不要把字幕塞进 `formats` 清晰度列表 |
| 视频总结 | 下载完成之后的另一个任务，读取已保存或临时文件 | 不要在 `extract_info` 的解析请求里同步调用模型 |
| 新平台 | 优先升级 `yt-dlp`。抖音是例外：上游会向使用者要 Cookie，也不认识精选页的 `modal_id`，所以由 `app/douyin.py` 请求公开详情接口 | 不要把整份 yt-dlp 提取器拷进仓库，也不要接收用户的平台 Cookie |

批量下载如果以后开放，仍然要走同一套链接校验和文件大小限制，不能因为会员标识就允许内网地址。

## 验证

- `pytest`：假的 `YoutubeDL` 覆盖清晰度收拢、非法链接、内网地址、任务完成后取文件、取走后文件不可再取。
- 页面：空链接、非法链接、解析成功后的清晰度切换、保存进度和浏览器下载。宽度收到手机尺寸时检查单列是否溢出。
- 真实网络只用于确认一条短的公开样例能解析出标题。下载链路的自动化不拉取长视频。
