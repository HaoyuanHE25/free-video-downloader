## 2. 建议阅读顺序

1. 先读 [需求分析.md](需求分析.md)，知道边界和「明确不做」。
2. 再读 [方案设计.md](方案设计.md)，了解接口分层与扩展点。
3. 涉及账号、额度、收款时读 [会员与支付.md](会员与支付.md)。
4. 想快速知道现状与已知限制，读 [项目总结.md](项目总结.md)。
5. 对外投放或做 SEO / GEO 时读对应两份增长文档。

## 3. 文档规范

- **标题**：统一写成 `# 随下：<主题>`。
- **摘要**：正文第一段用一到三句话说清本文解决什么问题、以什么为准。
- **链接**：文档之间用相对路径链接；引用代码时写相对仓库根的路径，例如 `app/membership.py`。
- **事实口径**：价格、限额、接口、端口以代码为准；文档与代码冲突时先改代码再回写文档。
- **范围声明**：`需求分析.md` 与 `方案评估与决策.md` 是阶段性快照，过期结论用「后续变更备注」标注，不直接改写历史判断。
- **敏感信息**：不写密钥、Cookie、真实账号或支付凭据；示例统一用 `example.com` 与测试卡号。
- **词汇**：对外统一说「解析引擎 / 下载引擎」，不提具体第三方库名。

## 4. 关键口径（速查）

| 项目 | 免费档 | 会员（¥9.9，永久） |
| --- | --- | --- |
| 每日下载次数 | 3 次 | 不限 |
| 同时下载 | 2 个 | 4 个 |
| 单文件上限 | 500MB | 2GB |
| 单次超时 | 10 分钟 | 30 分钟 |

- 登录方式：邮箱 + 密码，密码用 bcrypt 哈希存储；忘记密码走一次性重置令牌。
- 会员开通只认 Stripe webhook，回跳页面只做轮询展示。
- 每日次数在服务端按账号或 IP 原子计数，自然日 0 点重置。
