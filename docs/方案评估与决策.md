## 0. 执行摘要

**总体判断：技术架构方向正确，商业闭环尚未成立。**

- **技术侧得分 7.0 / 10**：Vue 3 + FastAPI + SSE 的分层清晰、技术栈成熟、后端 71 项测试通过、核心交互延迟达标；主要短板是**无鉴权与配额、SSE 并发无闸门、任务仅存内存、缺少可观测性与前端自动化测试**。
- **商业侧得分 6.5 / 10**：产品覆盖「保存 + 理解」两类真实需求，自托管与无登录带来差异化；但**版权与平台条款风险高、没有账号与支付闭环、赛道拥挤**，当前更适合个人/内部使用，不宜直接公开收费。
- **决策**：**需要调整优化，不需要重写**。保留 `Vite + FastAPI + SSE + 第三方解析库 + DeepSeek + 自绘 SVG 导图` 技术路线，按 P0（合规与访问控制）→ P1（可靠性与可观测）→ P2（性能与体验）推进。
- **若目标是公开收费运营**：P0 未完成前不建议上线，属阻断项。
- **若目标是个人/小团队自托管**：可维持现状使用，优先补 P1 中的模型重试、并发闸门与文档同步。

评分加权：商业 45% + 技术 55%，综合 **6.8 / 10（有条件通过）**（商业 6.5 已计入合规高风险折损，非六项简单平均）。

3. 先做自托管付费/捐赠或企业内部部署，而不是公开 SaaS。
4. 建立「下载 → 摘要 → 导图 → 问答」的结果沉淀（导出 Markdown/PDF、历史记录），提升留存。

**性能结论**：用户感知的「操作卡顿」风险低；真正的延迟来源是**外部平台解析与模型生成**，当前没有超时分级、重试与进度回退策略，弱网下体验不稳定。

### 4.3 架构合理性

**做得好：**

- SSE 统一封装（[sse.py](../app/sse.py)）：业务只写同步生成器，线程→异步队列桥接，统一心跳/错误帧/断线取消，避免每个接口重复实现。
- 摘要采用 `stream=True` + 半截 JSON 增量解析（StreamFields），大纲字符级下发、要点闭合即发，交互反馈快。
- 前端四模块用 `v-show` 常驻挂载，实现真正的状态隔离；Tab 使用 `role=tablist/tab/tabpanel` 与方向键切换；宽屏为左侧垂直吸顶栏，窄屏为顶部横向栏。
- 导图采用「结构树为源 → 自绘 SVG 布局」的单向数据流，服务端另用同一棵树下发 Mermaid 源码文本（页面当前只用结构树），避免预览与结构不一致。
- SSRF 防护统一走 `validate_public_url`，拒绝本机/内网/链路本地地址。

**结构性问题：**

- 部署态把静态页面与 API 合并进同一个 FastAPI 进程（[main.py](../app/main.py)），没有独立前端托管与网关；扩展与灰度受限。
- 所有状态在内存：下载任务、总结任务、字幕缓存、SSE 队列。**进程重启即丢**，无法多副本。
- SSE 每个请求创建一个业务线程（[sse.py](../app/sse.py#L72)），没有全局限流；AI 接口可被并发打满线程与模型额度。

### 4.4 可扩展性

| 扩展方向 | 现状成本 | 结论 |
| --- | --- | --- |
| 新增一个 AI 模块 | 低：新增生成器 + 路由 + 前端面板 | 友好 |
| 新增下载平台 | 低（升级解析引擎）~中（自研签名平台） | 抖音类平台需持续维护 |
| 提升并发 | 高：需引入队列（Redis/Celery）、限流、对象存储 | 当前模型不支持 |
| 多实例部署 | 高：任务与缓存需外置 | 当前不支持 |
| 增加用户体系 | 高：无数据库、无鉴权 | 需新增完整领域模型 |

**结论**：功能维度扩展性好，**规模维度扩展性差**；在单机小流量场景可接受。

- 71 项 pytest 覆盖 SSE、字幕切分、导图、问答、SSRF、下载任务等关键路径。

### 4.6 安全性

| 编号 | 风险 | 等级 | 证据/说明 | 建议 |
| --- | --- | --- | --- | --- |
| S1 | 接口无鉴权、无配额 | **高** | `/api/*` 全部匿名可调；SSE 每请求起线程，模型调用可被刷 | 增加访问口令/会话、IP 限流、每日额度 |
| S2 | 合规与滥用 | **高** | 下载能力对任何人开放；无用户授权确认 | 上线前加使用边界与确认流程 |
| S3 | SSRF 重定向绕过 | 中 | 入口已校验公网地址，但跳转后的内部请求依赖解析引擎，文档已列为已知限制 | 出口代理/网络层二次校验 |
| S4 | 提示注入 | 中 | 字幕文本作为不可信输入进入模型消息；未做指令隔离与输出约束审计 | 明确「资料仅作数据」、限制工具/输出格式、加敏感内容过滤 |
| S5 | 临时文件与磁盘 | 中 | 任务有 30 分钟 TTL 与失败清理，但进程崩溃会残留目录；下载单文件约 500MB、无磁盘配额 | 启动时清扫 + 磁盘水位保护 |
| S6 | 安全响应头缺失 | 低 | 未见 CSP/HSTS/X-Content-Type-Options 等中间件 | 增加安全头 |
| S7 | CORS 硬编码 | 低 | 仅允许 5173 两个来源（[main.py](../app/main.py#L43-L48)） | 改为环境变量配置 |
| S8 | 密钥与日志 | 低 | Key 仅在服务端 `.env`，前端不接触；但无密钥轮换与泄露检测 | 密钥管理规范化 |
| S9 | 渲染安全 | 低-中 | 导图标签清洗 + Vue 文本转义；自绘 SVG 只写入计算后的文本与属性，不注入外部 HTML | 保留清洗，补充 XSS 用例 |

**安全结论**：作为「本机自托管」工具，当前风险可接受；作为「公网服务」，**S1/S2 属上线阻断项**，S3/S4 需在上线前完成加固。

### 4.7 故障点清单（按发生概率排序）

1. 视频无字幕 → 总结/导图（URL 模式）/问答（URL 模式）返回 422；无 ASR 兜底。
2. 平台解析失败/签名失效（B 站、抖音、YouTube 风控）→ `/api/parse` 502。
3. DeepSeek 超时（120s）或限流 → SSE `error` 502/503，无自动重试。
4. 客户端断网 → SSE 断开即取消，无断点续传，用户需重新生成。
5. 服务重启 → 所有任务与缓存丢失（下载进度、总结任务、字幕缓存）。
6. 临时目录残留（崩溃/强杀）→ 磁盘占用增长，无启动清扫。
7. 并发突增 → 线程与模型调用无闸门，响应变慢甚至拖垮进程。
8. 导图节点过多 → 自绘布局超出视口，需要全屏并缩放查看（已提供「适应屏幕」与滚轮缩放）。

## 5. 综合研判与决策

### 5.1 结论

**需要调整优化；不需要推翻重做。综合判定为「有条件通过（Conditional Go）」。**

支撑依据：

1. **架构与实现质量足以支撑当前功能**：分层清晰、SSE 体系统一、后端测试通过、四模块状态隔离已验证，重写不会带来同等级收益，反而会丢失已验证的稳定性。
2. **阻断项集中在「对外运营」而非「内部可用」**：无鉴权、无配额、合规边界缺失是商业化前提问题，不是架构错误。
3. **主要技术债是「规模与运维」类**：内存任务、无监控、无 CI、文档漂移，均可在现有架构上增量解决。
4. **商业上尚不具备收费闭环**：没有账号/支付，且合规风险高，因此**不应以「公开 SaaS」作为当前目标**。

### 5.2 定位建议（决策前置条件）

| 定位 | 结论 | 必须完成 |
| --- | --- | --- |
| 个人/小团队自托管 | **可继续使用** | P1（可靠性、文档、CI）；建议补访问口令 |
| 企业内部工具 | **可试点** | P0 的访问控制 + 使用边界声明；P1 全部 |
| 公开免费服务 | **暂缓** | P0 全部 + 限流 + 合规评估 |
| 公开收费服务 | **不建议当前上线** | P0 全部 + 账号/支付 + 备案与法律意见 + 客服体系 |

### 5.3 调整优先级

#### P0（上线阻断项，必须先做）

| P0-2 | 合规边界 | 使用声明与用户确认、仅限有权保存内容、去掉「万能下载」表述、投诉渠道、生成式 AI 合规评估 | 页面与文档口径一致；法务/合规检查通过 |

## 7. 决策记录（ADR 摘要）

- **决策**：保留现有技术架构（Vue 3 + Vite + FastAPI + SSE + 第三方解析库 + DeepSeek + 自绘 SVG 导图），不重构；按 P0→P1→P2 增量优化。
- **背景**：功能已完整落地并通过 71 项后端测试；主要缺口为访问控制、合规边界、可靠性治理与文档一致性。
- **替代方案与否决理由**：
  - 全量重写为微服务/前后端完全分离：当前流量与团队规模不匹配，成本高、收益低，否决。
  - 直接公开 SaaS：P0 未完成，合规与滥用风险不可控，暂缓。
  - 放弃下载能力只做总结：会丢失主要差异化，且现有下载模块已验证稳定，不采纳。
- **后果**：短期内保持单机部署；在 P0 完成前限制使用范围；P1 完成后具备对外试点条件。
