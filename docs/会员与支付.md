# 随下：会员与支付（Stripe）

本文档记录「随下」会员购买功能的设计、Stripe 使用引导、离线测试方案与上线检查清单。

## 1. 目标与边界

目标：访客免费可用；付费后放宽下载资源上限。**不新增**批量下载、字幕翻译等未确认功能。

会员权益（一次性买断，永久有效）：

| 项目 | 游客 | 会员 |
| --- | --- | --- |
| 每日下载次数 | 3 次 | 不限 |
| 同时下载数 | 2 | 4 |
| 单个文件体积 | 500MB | 2GB |
| 单次下载超时 | 10 分钟 | 30 分钟 |
| 价格 | 免费 | ¥9.9 / 永久 |

价格与币种只写在服务端常量里（`app/billing.py`），前端只负责展示，**绝不接受前端传入金额**。

每日次数的实现（`membership.consume_daily_quota`）：非会员每次发起下载先原子占用一次额度，记在 `download_usage` 表里，按服务器本地时区的自然日（0 点）重置；已登录的非会员按账号计次，未登录游客按 IP 计次，会员直接跳过。任务没能进入队列（例如队列已满）时会把刚占用的一次退回，避免白扣次数。用尽后 `/api/download` 返回 429 并提示升级会员。

## 2. 用户体系：邮箱 + 密码

注册、登录、重置密码三条流程：

1. **注册** `POST /api/auth/register`：邮箱 + 密码（至少 8 位），密码用 bcrypt 加盐哈希后存库，注册成功直接登录
2. **登录** `POST /api/auth/login`：邮箱 + 密码比对，失败统一返回「邮箱或密码不正确」，不区分账号是否存在
3. **找回密码** `POST /api/auth/request-reset`：生成 15 分钟一次性 token，重置链接直接返回给页面并记录到后端日志（不再依赖邮件）；`POST /api/auth/reset` 用 token 设置新密码，成功后自动登录并使该账号其他会话失效

登录态统一写 `sx_session` Cookie（HttpOnly / SameSite=Lax / 30 天，剩余不足 7 天时访问 `/api/me` 自动续期）。

防枚举与防爆破：重置接口对未注册邮箱也返回结构一致的链接（token 不落库，重置时必然失败）；登录连续失败 8 次后锁定 5 分钟；重置链接 60 秒冷却。

安全性：密码只存 bcrypt 哈希，永不回传、不落日志；历史无密码账号（旧的邮件链接登录）已作废，无法通过会话校验。

## 3. 购买流程

```
浏览器               后端                            Stripe
  |  POST /api/billing/checkout |                    |
  |--------------------------->|  建订单(pending)    |
  |                            |  Session.create --->|
  |                            |<--- session.id/url  |
  |<---- {url} ----------------|                     |
  |  跳转 Stripe Checkout --------------------------->|
  |                    用户完成支付                    |
  |<---- 跳回 /?checkout=success&session_id=... ------|
  |  GET /api/billing/orders/{id}（轮询）              |
  |                            |<---- webhook ------ |
  |                            | 校验+幂等+开通会员   |
  |<---- {status: paid, member: true}                 |
```

**会员只能由 webhook 开通。** 支付成功回跳页只做轮询展示，绝不在 GET 成功页里直接改会员状态，避免用户伪造 URL 白拿会员。

## 4. 数据模型（SQLite）

数据库文件：`data/app.sqlite3`（已加入 `.gitignore`），可用 `MEMBERSHIP_DB_PATH` 覆盖。

| 表 | 作用 | 关键约束 |
| --- | --- | --- |
| `users` | 用户 | `email UNIQUE`，`password_hash` 为 bcrypt 哈希 |
| `reset_tokens` | 密码重置 | 主键为 token 的 SHA256，`expires_at`、`used_at` |
| `sessions` | 登录态 | 主键为 Cookie token 的 SHA256，30 天过期 |
| `orders` | 订单 | `stripe_session_id UNIQUE` |
| `memberships` | 会员 | `user_id` 主键，天然一人一条 |
| `processed_events` | webhook 去重 | `event_id` 主键 |
| `download_usage` | 非会员每日下载次数 | `(subject, day)` 主键，`subject` 为 `user:<id>` 或 `ip:<addr>` |

## 5. 幂等设计（四层）

1. **下单幂等**：同一用户 25 分钟内已有 pending 订单时直接复用原 Checkout 链接，不会生成第二笔付款。
2. **Stripe 请求幂等**：`StripeClient.checkout.sessions.create(params, options={"idempotency_key": "checkout:{order_id}"})`，网络重试也不会创建两个 Session。
3. **数据库唯一约束**：`orders.stripe_session_id UNIQUE`、`memberships.user_id` 主键 + `INSERT OR IGNORE`。
4. **事件去重**：`processed_events` 按 `event.id` 记录，Stripe 重投同一事件不会重复开通。

额外校验（任一不符即拒绝开通）：

- `session.mode == "payment"`
- `session.payment_status == "paid"`
- `session.amount_total == 990` 且 `session.currency == "cny"`
- `metadata.order_id` 能找到订单，且 `metadata.user_id` 与订单归属一致

## 6. 安全清单

- Webhook 必须用**原始请求体**验签：`stripe.Webhook.construct_event(payload, sig, secret)`，验签失败返回 400。
- 密码只存 bcrypt 哈希（cost 12，测试用 `BCRYPT_ROUNDS=4`）；重置 token 只存哈希、单次使用、15 分钟过期；登录态 Cookie `HttpOnly` + `SameSite=Lax`。
- 登录失败统一提示，连续 8 次失败锁定 5 分钟；重置链接 60 秒冷却。
- 非会员每日 3 次下载在服务端按账号/IP 原子计数，前端无法伪造；`limits` 里的额度仅供参考。
- 购买、查询订单都要求登录，且只能查看自己的订单。
- 金额、币种、商品名全部服务端常量，忽略任何前端传值。
- 生产环境禁止 Fake 支付通道（见下）。
- 密钥只放 `.env`（已在 `.gitignore`），不写进代码、不入库、不返给前端。

## 7. 环境变量

```ini
# 支付通道：留空则按是否配置 STRIPE_SECRET_KEY 自动判断
BILLING_PROVIDER=

# Stripe（测试密钥以 sk_test_ 开头）
STRIPE_SECRET_KEY=sk_test_xxx
STRIPE_WEBHOOK_SECRET=whsec_xxx

# 对外访问地址，用于拼接支付回跳地址；留空则用请求自身的 host
# 直接用后端 8000 端口打开页面时留空即可；用 Vite 5173 开发时填 http://localhost:5173
PUBLIC_BASE_URL=http://127.0.0.1:8000

# 生产环境请设为 production：禁用 Fake 支付
APP_ENV=development

# 登录 Cookie 的 Secure 属性默认按请求协议自动判断（HTTPS 自动开启）。
# 只有需要强制开关时才填 1/0
COOKIE_SECURE=

# bcrypt 计算强度，默认 12；测试可设 4 加速
BCRYPT_ROUNDS=

# 部署在 Nginx / 云负载均衡后面时设为 1，游客每日次数才会按真实客户端 IP 统计
TRUST_PROXY=

# 浏览器写操作的 Origin 白名单，逗号分隔；PUBLIC_BASE_URL 与本站 Origin 自动放行
ALLOWED_ORIGINS=
```

## 8. 给第一次用 Stripe 的完整引导

### 8.1 先分清测试模式与真实模式

Stripe 后台左上角有 **测试模式（Test mode）** 开关。测试模式下用 `sk_test_` 密钥 + 测试卡号，**不会真扣钱**；真实模式用 `sk_live_` 密钥，会真实扣款。开发阶段只用测试模式。

### 8.2 拿到测试密钥

1. 登录 <https://dashboard.stripe.com>
2. 打开右上角 **Test mode**
3. 左侧 **Developers → API keys**
4. 复制 **Secret key**（`sk_test_...`），填到 `.env` 的 `STRIPE_SECRET_KEY`

### 8.3 安装 Stripe CLI（用于本地接收 webhook）

Stripe 需要主动把「支付成功」事件推给后端。本地 `127.0.0.1` 外网访问不到，所以用官方 CLI 把事件转发进来：

```powershell
# Windows 任选一种
scoop install stripe
# 或到 https://github.com/stripe/stripe-cli/releases 下载 stripe_windows_x86_64.zip，解压后把 stripe.exe 放进 PATH
```

然后：

```powershell
stripe login
# 浏览器确认，会把测试密钥授权给 CLI

stripe listen --forward-to 127.0.0.1:8000/api/billing/webhook
```

终端会输出一行 `whsec_...`，把它填到 `.env` 的 `STRIPE_WEBHOOK_SECRET`。**这个 CLI 必须一直开着**，否则本地收不到支付成功事件。

> 上线时不用 CLI：在 Dashboard → Developers → Webhooks 添加 `https://你的域名/api/billing/webhook`，订阅 `checkout.session.completed`、`checkout.session.async_payment_succeeded`、`checkout.session.expired`，把该端点的签名密钥填到 `STRIPE_WEBHOOK_SECRET`。

### 8.4 用测试卡走一遍

1. 启动后端 `python -m uvicorn app.main:app --host 127.0.0.1 --port 8000`
2. 启动前端 `cd web; npm run dev`，打开 <http://localhost:5173>
3. 右上角「登录」→ 没有账号先「注册」，填邮箱和密码
4. 点「¥9.9 开通会员」→ 跳到 Stripe Checkout
5. 卡号 `4242 4242 4242 4242`，有效期填任意未来日期，CVC 任意三位，其余信息随意
6. 支付后跳回首页，页面轮询到 `paid` 后显示「会员」

常用测试卡：

| 卡号 | 效果 |
| --- | --- |
| 4242 4242 4242 4242 | 支付成功 |
| 4000 0000 0000 0002 | 被拒绝 |
| 4000 0000 0000 3220 | 需要 3D Secure 验证 |

### 8.5 人民币收款提示

本项目使用 `currency="cny"`、`unit_amount=990`。Stripe 人民币收款要求账户具备对应国家/地区资质；如果测试时提示币种不支持，可临时把 `app/billing.py` 里的币种改成 `usd` 并把金额改成 `990`（$9.90）验证流程，正式收款前再按你的账户资质确定币种。

## 9. 没有外网时怎么完整测试

系统内置一个 **本地模拟收银台**：不配置任何 Stripe 密钥时自动启用 `fake` 通道。

- 点「开通会员」不会跳 Stripe，而是打开本地页面 `/api/billing/fake/checkout/{order_id}`
- 页面上有「模拟支付成功」按钮，提交后执行**与真实 webhook 完全相同**的开通函数（同样的金额校验、事件去重、会员写入）
- 全过程不访问外网，可验证：登录、下单、回跳轮询、开通会员、重复提交不重复开通、限额生效

强制启用/关闭：`BILLING_PROVIDER=fake` 或 `BILLING_PROVIDER=stripe`。`APP_ENV=production` 时 fake 通道直接不可用，防止误上线。

## 10. 接口清单

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/auth/register` | 注册（邮箱 + 密码），成功即登录 |
| POST | `/api/auth/login` | 邮箱 + 密码登录 |
| POST | `/api/auth/request-reset` | 生成一次性重置链接（返回 `reset_url` 并写日志） |
| POST | `/api/auth/reset` | 用重置 token 设置新密码，成功即登录 |
| POST | `/api/auth/logout` | 退出登录 |
| GET | `/api/me` | 当前用户、会员状态、当前限额、价格 |
| POST | `/api/billing/checkout` | 创建/复用收银台链接（需登录，已是会员返回 409） |
| GET | `/api/billing/orders/{session_id}` | 轮询订单状态，仅本人可见 |
| POST | `/api/billing/webhook` | Stripe 回调，验签 + 幂等开通 |
| GET | `/api/billing/fake/checkout/{order_id}` | 仅 fake 通道：本地模拟收银台 |
| POST | `/api/billing/fake/pay` | 仅 fake 通道：模拟支付成功 |

## 11. 支付故障排查（服务器）

「点击开通会员没有反应/没有支付页」按下面顺序定位，两分钟内可定案：

1. **先确认当前支付通道**。在项目根执行：

   ```bash
   .venv/bin/python -c "from app import billing; print(billing.provider())"
   ```

   输出 `fake` 说明没有读到 Stripe 密钥——表现为跳转到本地模拟收银台页（`/api/billing/fake/checkout/...`）而不是 Stripe，这是最常见的误报原因。补齐 `.env` 的 `STRIPE_SECRET_KEY` 后重启即恢复。
2. **看后端是否存活**：`ss -tlnp | grep 8000`；Nginx 代理路径 `curl -s -X POST http://127.0.0.1/api/billing/checkout` 预期返回 401「请先登录」（未带 Cookie 时），若返回 502 则是 Nginx 到后端不通。
3. **看 Nginx 访问日志的真实状态码**：`grep billing/checkout /www/wwwlogs/<站点>.log`。
   - 200：后端已正常返回收银台链接，问题在前端展示或通道模式（回到第 1 步）。可用响应字节数辅助判断：Stripe 链接约 200 字节，fake 链接约 141 字节。
   - 401：未登录或 Cookie 失效。
   - 403「跨站请求被拒绝」：访问地址与 `PUBLIC_BASE_URL`/`ALLOWED_ORIGINS` 不一致。
   - 502「支付暂时不可用，请稍后再试」：创建 Stripe 会话失败，后端日志会有 `创建支付会话失败` warning（密钥无效或出站网络不通，用 `curl -sI https://api.stripe.com` 测连通性，返回 401 即为可达）。
4. **支付成功但会员未开通**：Webhook 没打通。确认 Dashboard 端点地址、签名密钥与 `.env` 一致，且事件订阅包含 `checkout.session.completed`。

## 12. 上线前检查

- [ ] 服务器上 `billing.provider()` 输出 `stripe`（防止误用 fake 通道上线）
- [ ] `APP_ENV=production`、`COOKIE_SECURE=1`，站点走 HTTPS
- [ ] 使用 `sk_live_` 密钥，Dashboard 配好正式 webhook 并替换 `STRIPE_WEBHOOK_SECRET`
- [ ] `PUBLIC_BASE_URL` 改成真实域名（影响支付回跳）
- [ ] `BCRYPT_ROUNDS` 保持默认 12
- [ ] 备份 `data/app.sqlite3`
- [ ] 用测试卡在测试模式回归：重复点击购买只产生一笔订单、重复 webhook 只开通一次
